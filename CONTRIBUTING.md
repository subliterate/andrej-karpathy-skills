# Contributing

## Scope

This repository stays intentionally small. Contributions should keep the guidance concise, actionable, and easy to merge into an existing `CLAUDE.md`.

## Before Opening a Pull Request

1. Confirm the change supports one of the four core principles.
2. Prefer clarifications and examples over adding new abstraction or ceremony.
3. Keep wording direct and implementation-focused.
4. Avoid expanding the repository with tooling unless it helps maintain the existing content.

## Content Guidelines

- Keep examples short and concrete.
- Preserve the current tone: practical, sceptical of bloat, and explicit about trade-offs.
- If you adjust installation instructions, update every relevant path in the README.
- If you change plugin metadata, make sure it stays aligned with the README and the root files shipped by the repository.

## Pull Request Checklist

- State the user-facing benefit in one or two lines.
- Mention any files that need to stay in sync.
- Note whether the change is documentation-only or has validation steps.
